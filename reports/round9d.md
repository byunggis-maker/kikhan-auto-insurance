=== 라운드 9d 보고서 ===

> 미계산 합계 안전장치와 법령 원문 미리받기(번들) 방식을 넣고 https://kikhan-auto-compass-v6.vercel.app 에만 배포했습니다.
> 앱(Vercel)은 이제 법령 API를 부르지 않습니다. 원문은 칸 맥에서 `npm run laws:fetch`로 받아 넣어야 화면에 나옵니다(아직 0개 → 지금은 "원문 갱신 필요").

**1. 미계산 합계 안전장치**

- '미계산' 줄이 하나라도 있으면 받을 돈(확정·추정 포함), 받을 곳별, 과실 시나리오의 받을 돈이 **"70만 원 + 미계산"**처럼 보이고 옆에 **"일부 미계산 포함 — 실제 금액은 이보다 클 수 있음"**.
- 문구와 표시 방식은 한 곳(`lib/report/review.ts`의 PARTIAL_NOTE·totalText)에서 관리하고 화면·엑셀·PDF가 같이 씁니다.
- 엑셀은 그 칸을 숫자가 아닌 글자("700,000원 + 미계산")로 두어 합계로 확정 계산되지 않게 했습니다. 미계산이 없으면 지금처럼 숫자 칸입니다.
- 내가 낼 돈·'내 보험이 상대방에게 줄 돈'은 바꾸지 않았습니다.
- 참고: 지금의 미계산 2건(상대 운전자 가족 동승자, 무보험 상대 차 동승자)은 상대 차량 탑승자가 받는 돈이라 피보험자 측 '받을 돈'에는 원래 들어가지 않습니다. 지시대로 합계 전체에 문구를 붙였으므로 보수적인 표시입니다.
- 테스트: 두 경우 모두 엑셀 요약의 받을 돈·받을 곳별 칸이 "○원 + 미계산", PDF 글자에 "+ 미계산"과 문구가 있는지(실제 PDF를 만들어 글자를 읽어 확인), 미계산이 없으면 숫자인지.

**2. 법령 원문 미리받기 스크립트**

- `v6/scripts/fetch-laws.ts`, 실행 `npm run laws:fetch`(v6 폴더).
- 받을 조문을 자동으로 모읍니다: 코드(lib·components·app)의 "○○법 제N조", "시행령 [별표 N]" 인용 + 기본 조문. 지금 16개입니다:
  - 자동차손해배상 보장법 제3·5·10·30조
  - 같은 법 시행령 제3조, 별표1·2
  - 민법 제396·760·763조
  - 상법 제680·682·724·726조의2·729·737조
- 지시의 민법 760·763·396조는 현재 코드에 인용이 없어 기본 조문으로 넣었습니다. 약관 원문 안의 민법 제777·1000조 등은 앱 코드의 인용이 아니라서 넣지 않았습니다.
- 저장: `v6/data/laws/<id>.json`(조문마다)과 `v6/data/laws/index.json`(앱이 읽는 묶음). 각 기록에 법령명, 조문번호, 조문 원문, 시행일, 받은 날짜(fetchedAt), 출처 URL이 들어갑니다.
- OC는 `v6/.env.local`의 `LAW_OC`에서 읽습니다(.env*는 커밋되지 않음, 화면·로그에 값을 찍지 않음).
- 인증 실패·IP 미등록·API 미신청·JSON 아님·인터넷 끊김이면 원인을 한국어로 찍고 **파일을 하나도 쓰지 않습니다.** 조문 하나만 못 받으면 그 조문의 예전 파일을 남깁니다.
- LAW_OC 없이 실행해 확인했습니다: 안내 문구를 찍고 멈췄고 data/laws는 바뀌지 않았습니다.
- 실제 API로는 실행하지 못했습니다(이 컴퓨터에 OC 값과 IP 등록이 없음). 응답 모양은 가짜 서버로 시험했습니다(원문·시행일·받은 날짜·URL 저장, Referer, 거절 시 멈춤, 예전 기록 유지).

**3. 앱 연결**

- 외부 법령 API 호출 코드를 없앴습니다(`lib/law/client.ts` 삭제, Vercel의 LAW_API_OC 사용 안 함). 남은 `lib/law/parse.ts`는 응답을 펴는 순수 함수로, 스크립트만 씁니다.
- 결과 화면에 **근거 법령** 칸을 더했습니다. 검토서 근거에 나온 조문마다 원문이 있으면 원문(펼쳐 보기)과 "원문 기준일: YYYY-MM-DD (시행일 YYYY-MM-DD)", 없거나 받은 지 180일이 넘으면 **"원문 갱신 필요"** 배지를 보입니다. 계산은 막지 않습니다.
- 약관 질의도 앱에 든 원문으로 인용을 대조하고 기준일을 붙입니다. 원문이 없는 법은 "원문 갱신 필요", 원문은 있는데 그 조문이 아니면(지어낸 조문 등) "원문에서 확인되지 않음"입니다. 9b의 "법령 원문 연결 전"은 이것으로 바뀌었습니다.

**4. 문서**

- `v6/docs/법령-갱신.md`: 처음 준비(open.law.go.kr 신청, 도메인·IP 등록, IP 확인 명령), OC 넣기, `npm run laws:fetch`, 저장소에 올리기, 배포, IP가 바뀌었을 때 다시 등록하는 순서. 명령은 모두 복사해 붙여 넣는 코드 블록입니다.
- 올리기 단계는 맥의 저장소 폴더에 올리지 않은 Streamlit 작업(app.py 등)이 있어 그대로 `git add/commit/push`하면 그 파일과 엉키므로, 잠깐 쓰는 별도 폴더(git worktree)에서 `data/laws`만 올리게 했습니다. force push는 쓰지 않습니다.
- `docs/키-갱신.md`의 법령 부분은 이 문서로 안내를 옮겼습니다.

**5. 검증·배포**

- 테스트 30개 파일 325개 통과(새 tests/ui/round9d.test.ts 11개, 예전 법령 API 시험은 스크립트 시험으로 옮김), 타입 검사·린트·빌드 통과. Next.js 16.4.6.
- 배포 주소 확인(390×844, 화면에서 직접 입력, 내 과실 30%, 피보험자(나)와 상대 차량 탑승자 모두 5급·위자료 100만 원):

| 경우 | 받을 돈 | 근거 법령 | 엑셀 받을 돈 | PDF |
|---|---|---|---|---|
| 상대 차량 동승자 | 70만 원(숫자) | 시행령 별표1 — 원문 갱신 필요 | 700,000(숫자) | 문구 없음 |
| 상대 운전자 가족 동승자 | 70만 원 + 미계산, 문구 2곳, 받을 곳별 제목에 문구 | 시행령 별표1 — 원문 갱신 필요 | "700,000원 + 미계산" + 문구 | "+ 미계산"과 문구 있음 |

- 원문과 기준일이 실제로 보이는 모습은 원문이 아직 없어 배포 주소에서 확인하지 못했습니다. 화면에 쓰는 함수(원문 있음 → 원문·기준일, 180일 초과·없음 → 배지)는 테스트로 확인했습니다.
