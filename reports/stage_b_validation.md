## 백업 및 변경

수정 전 파일을 `backups/stage_b_20261007_210905/`에 보관했습니다. `app.py`, `requirements.txt`, `insurance_ocr/image_reader.py`, `insurance_ocr/policy_parser.py`가 포함됩니다. 정상 음성 관련 여섯 함수는 백업과 AST가 동일함을 테스트했습니다. 키·환경변수 값은 출력하거나 저장하지 않았으며 `.env`와 secrets 파일은 Git 추적 대상이 아닙니다.

문서 업로드 UI → 공통 키 로더 → 문서 API → 검증 → 수정 가능한 증권 입력칸을 연결했습니다. 텍스트형·스캔형 PDF는 [OpenAI 공식 파일 입력 규격](https://developers.openai.com/api/docs/guides/file-inputs)에 따라 input_file로 전달합니다. HEIC는 pillow-heif로 읽고 JPEG로 변환합니다. 문서 기본 모델은 gpt-4.1-mini이며 POLICY_READER_MODEL로 변경할 수 있습니다. 음성 모델·코드는 변경하지 않았습니다.

앱 제한: 20MB, PDF 30페이지, 이미지 4천만 화소. 암호화·손상 파일은 거부합니다. API 요청은 최대 90초, 자동 재시도 없이 실행되며 응답 본문·키를 오류 메시지에 노출하지 않습니다.

## 검증 결과

- 임시 Python 3.12 환경에 requirements 설치 및 pip check 통과. 기존 .venv/.venv_arm 이미지 패키지는 현재 x86_64 Mac과 아키텍처가 달라 사용하지 않았습니다.

- 텍스트형 영문 PDF에서 원문 담보명 Own Vehicle Damage Limit 및 KRW 금액 표기를 확인하고 정확한 별칭·통화 처리를 추가했습니다. 한국어 외의 일반적인 담보 번역은 수행하지 않습니다.
- 자동 테스트 6개: 형식별 전처리, 손상·암호화·대용량 거부, API 입력/미완료 처리, 불확실한 항목, 자동 채움·수정·빈칸, 계산·합계·엑셀 구조 및 수식 주입 방지, 음성 함수 보존. 테스트 메서드 일부는 여러 검증 항목을 포함합니다.
- `python -m unittest discover -s tests -v`, Python 컴파일, `git diff --check` 통과. 프론트엔드 npm 프로젝트가 아니므로 npm 빌드는 없습니다.

## 계산 범위와 근거

직접 추출한 개인용 약관 PDF 57–58페이지(인쇄 55–56), 제24조를 사용합니다. 원문 파일 SHA-256이 일치해야 계산합니다. 기존 JSON의 페이지 안내는 실제 해당 조항 위치와 달라 그대로 사용하지 않았습니다.

부분손해 최초 청구에 한해 인정 손해액(가입한도·보험가액 이내) + 인정 비용 - 확정 자기부담금을 계산합니다. 인정 비용은 가입금액과 관계없이 보상한다는 조항을 반영했습니다. 과실률을 임의로 일괄 적용하지 않습니다. 실제 계약 약관·면책·특약 적용을 사용자가 확인하고 손해액·비용·보험가액·확정 공제액을 입력해야 합니다. 전손·가입금액 전액 지급·기지급금/구상금은 별도 검토 대상으로 보류합니다.

신체 담보의 급별 한도·지급기준, 입원일수·치료비의 적용 규정, 배상책임·공제 규정을 확인할 수 없는 경우 금액을 만들지 않습니다. 미선택 기본담보도 가입 및 필요 여부 확인 행으로 표시하며, 부족한 입력/근거를 표시합니다. 미계산 항목은 합계 및 엑셀 합계에서 제외합니다.

## 미검증 및 남은 문제

실제 사용자 증권·가입증명서, 보험사별 계약 약관 적용, 신체 담보/다른 약관의 금액 산정, 실제 브라우저 다운로드 조작 및 Excel 앱의 시각적 출력, Vercel 요청 제한·설치·실행시간·배포는 미검증입니다. 여기서 단계 B가 모든 환경에서 통과했다고 주장하지 않습니다.


## 추정 총계 변경 (사용자 요청 반영)

수정 전 `backups/estimate_total_20261007_212323/`에 app.py·검증 코드·이 보고서를 백업했습니다. 음성 및 문서 API 코드는 변경하지 않았습니다.

- 수식에 필요한 값이 있는 자차 추정액은 약관 적용·면책 확인이 미완료여도 조건부 추정액으로 총계에 포함합니다. 전손 등 기존 부분손해 수식을 적용할 수 없는 경우는 자동 금액을 만들지 않습니다.
- 자동 계산이 어려운 담보에는 사용자가 임시 추정액과 사유를 입력할 수 있습니다. 사용자 입력액은 총계에 포함하고 약관상 계산액이 미확정임을 표시합니다. 미입력은 금액 미정으로 남기며 0원으로 간주하지 않습니다.
- 담보별 지급조건·면책조건·계산식은 기존 약관 정리자료에서 표시합니다. 원문과 실제 계약을 대조하지 않은 페이지·자료는 미검증으로 표시합니다.
- 같은 손해에 대한 담보별 입력액도 요청에 따라 단순 합산하되 중복 지급 조정이 필요하다는 사유를 기록합니다. 따라서 총계는 조정 전 추정 총계입니다.
- 화면과 엑셀 합계가 일치하며, 기존 계산제외항목 시트는 확인필요항목으로 변경했습니다. 조건부 추정액·사용자 임시 추정액의 합산 여부와 사유를 함께 기록합니다. 일부 금액이 미정이면 총계에도 표시합니다.
- 자동 테스트 7개, Python 컴파일, git diff --check 통과. 실제 보험금 지급 결과와 실제 브라우저/Excel 앱의 시각적 결과는 미검증이며 배포하지 않았습니다.


### 미정 표시 통일

금액을 정할 수 없는 항목의 예상 지급액·청구 검토금액·엑셀 합산 상태를 모두 「미정」으로 통일했습니다. 부족한 입력과 지급기준·면책·공제 등 약관 확인 사유는 담보별 산정근거 및 확인필요항목 시트에 기록합니다. 임시 추정액을 사용자가 입력한 항목은 기존 선택대로 총계에 포함합니다.
