# 키칸 자동차보험 보상 나침반 V6 — 마스터 설계

> 이 문서는 모든 라운드의 기준이다. 1부는 칸이 정한 설계(라운드 0 수정 반영), 2부는 라운드 0에서 칸이 답한 결정 사항, 3부는 약관 대조 결과, 4부는 아직 열린 질문, 부록 A는 이식한 V2 코드의 출처다.
> 1부와 2부가 충돌하면 2부(나중 결정)가 우선한다.

# 1부. 설계 원문

역할: 칸이 방향을 정하고, 별도 채팅의 Claude AI가 보고서를 검산한다. 개발 책임자(Claude Code)는 만들고 보고한다.

## 1. 앱의 목적
- 사고 낸 운전자 본인이 보상담당자 없이 "누가, 어느 보험에서, 어떤 담보로, 대략 얼마를, 무슨 서류로" 받는지 추정하게 한다.
- 화면과 계산은 보상담당자의 처리 순서를 따른다: 사고 접수 → 면책·제한 확인 → 사람·물건 정리 → 담보 매칭 → 손해액 산정 → 지급액 조정 → 서류 안내.
- 계산 단위는 담보가 아니라 사람 한 명, 물건 한 개다. 운전자, 동승자 각각, 상대방을 따로 카드로 만든다.

## 2. 절대 규칙
- 로그인, 비밀번호, 카카오 인증 없음. 주소만 열면 바로 쓴다.
- Supabase를 포함한 어떤 데이터베이스도 쓰지 않는다. 사고 정보는 서버에 저장하지 않고, 진행 상태는 브라우저 localStorage에만 저장한다(읽기·쓰기 모두 try/catch).
- 모든 금액 옆에 계산식과 약관 조항(별표 번호)을 표시한다.
- 결과 화면 맨 위에 "추정액이며 확정 금액은 보험사가 정합니다"를 표시한다.
- 작업은 v6/ 안에서만. compass/(V2), Streamlit 파일은 읽기만 하고 수정하지 않는다. (원문에 있던 v4/ 폴더는 이 저장소에 없다 — 결정 기록 D-28)
- 화면 글자는 전체적으로 진하게. 추정 값과 인식된 값만 연한 청색 계열로 구별한다.

## 3. 근거 자료(우선순위 순)
- data/raw/policies/ 안의 자동차보험 약관 PDF(개인용, 업무용, 영업용, 이륜차). 별표 지급기준이 계산의 최종 근거다.
- 자동차손해배상보장법과 시행령(책임보험 한도, 상해급수 표, 정부보장사업).
- V2 코드는 부품 참고용이다. 음성→문자 변환, 증권·서류 인식(PDF, HEIC, JPEG), 개인정보 가림, 엑셀 저장만 참고해 다시 구현한다. V2의 화면 순서와 담보 단위 계산은 쓰지 않는다.
- 단, 6장의 이식 로직은 예외.
- 약관과 다르게 가정한 값과 금액 기준(한도, 사고부담금, 일용근로자 임금 등)은 v6/lib/claim/standards.ts 한 파일에 근거와 함께 모으고, 보고서에 반드시 적는다.

## 4. 데이터 구조
- Accident: 일시, 장소, 경위, 사고 유형(차대차, 차대사람, 단독, 뺑소니·무보험).
- Policy(내 보험·상대 보험): 보험 종류(개인용·업무용·영업용·이륜차), 보험사, 가입담보와 가입금액, 운전자 범위, 자기부담금, 대인Ⅱ 가입 여부.
- Victim: 운전자 본인 / 가족 동승자 / 남 동승자 / 상대방. 사람마다 카드 1개. 기명피보험자와의 관계 포함.
- Property: 내 차 / 상대 차·물건. 물건마다 카드 1개.
- LossItem: 항목 코드, confirmed(확정 금액, 서류 근거), estimated(추정 금액), source(서류 | 약관 기준 | 사용자 추정 | 앱 기본값), requiredDocs(필요 서류 목록).
- 카드마다 userTotal(사용자가 직접 넣는 합계 추정).

## 5. 확정·추정 이중 계산
- 확정 계산: confirmed 값만으로 엔진을 실행한다.
- 추정 포함 계산: confirmed가 빈 칸만 estimated로 채워 엔진을 다시 실행한다.
- 추정분 = 두 결과의 차이. 단순 덧셈 금지(하한·한도·자기부담금 때문에 비선형).
- 같은 칸에 둘 다 있으면 confirmed 우선. estimated는 참고로 청색 표시.
- 둘 다 없으면 "입력 필요"로 남기고 합계에 넣지 않는다.
- 항목 없이 userTotal만 있으면 "항목 미분류 손해(추정)"로 계산하고 치료관계비 하한은 적용하지 않는다. "항목을 나누면 더 정확해집니다"를 안내한다. 항목과 userTotal이 둘 다 있고 다르면 차이를 표시한다.
- 결과는 담보별·사람별로 확정액, 추정 포함액, 추정분을 따로 낸다.

## 6. 계산 엔진 순서
(1) 면책·제한
- 음주·무면허·마약: 담보는 지급하되 사고부담금을 "내가 낼 돈"에 표시.
- 운전자 범위 위반: 대인Ⅰ과 대물배상 의무가입한도(2천만 원)까지만 지급, 나머지 담보는 면책 표시.
- 기명피보험자의 부모·배우자·자녀는 내 대인Ⅱ 면책.
- 고의 사고: 계산하지 않고 안내만.

(2) 담보 매칭
- 나(운전자) → 상대 대인Ⅰ·Ⅱ, 부족분·내 과실분은 내 자동차상해 또는 자기신체사고
- 가족 동승자 → 상대 대인(상대 과실분) + 내 대인Ⅰ, 내 대인Ⅱ는 면책, 부족분은 내 자동차상해
- 남 동승자 → 상대 대인 + 내 대인Ⅰ·Ⅱ(공동 배상), 호의동승 감액 검토 표시
- 상대방 → 내 대인Ⅰ·Ⅱ, 보험료 할증 안내
- 내 차 → 상대 대물(상대 과실분) + 내 자기차량손해(내 과실분 − 자기부담금)
- 상대 차·물건 → 내 대물배상, 한도 초과분은 본인 부담
- 무보험·뺑소니 → 내 무보험차상해, 미가입이면 정부보장사업

(3) 손해액 산정: 약관 별표 기준으로 치료관계비, 향후치료비, 휴업손해, 위자료, 상실수익, 수리비, 대차료·휴차료, 시세하락, 견인비.

(4) 지급액 조정: 과실상계 → 치료관계비 하한 → 경상(12~14급) 운전자 구상 → 담보 한도 → 자기부담금.

(5) 중복 차감: 뒤 순위 담보는 "실제손해 − 앞 순위 지급액"만 준다.
- 과실을 모르면 0·30·50·70% 시나리오를 한 번에 계산한다.
- compass(V2)의 아래 로직만 예외로 v6에 이식한다. 나머지 V2 담보 단위 계산은 쓰지 않는다. (원본 파일·줄 번호는 부록 A)
  - 치료관계비 하한·경상(12~14급) 구상: compass/lib/engine/fault.ts `excessOverCompulsory()`, coverages/liability-bodily-1.ts `liabilityBodily1()`, 규칙값 data/rules/standard/fault.json `fault.medicalFloor`
  - 중복 차감: fault.ts 77-78행, coordinate.ts `deductionFor()`, coverages/own-damage.ts 상대 대물 공제
  - medicalFloor 는 productLines ["personal"](현대해상 2025-11-26 개정 별표4)로만 검증됨. 업무용·영업용·이륜차에서 호출되면 결과에 '미검증: 해당 약관 대조 필요'를 붙인다.
- 사람별 지급 합계는 그 사람의 실제손해를 넘을 수 없다.

## 7. 화면 7단계(모바일 우선, 한 화면에 질문 하나)
1 사고 접수(음성 또는 글) → 2 사람·물건 정리 → 3 내 보험(증권 사진 인식 또는 직접 입력) → 4 상대 보험 → 5 면책·과실(과실 모르면 범위 선택) → 6 손해 입력 → 7 보상 검토서.
- 6단계 청구란: 가입담보에 있는 담보만 보인다. 손해 항목 하나 = 카드 하나. 카드에 항목 이름과 한 줄 설명, "서류로 확인한 금액(확정)", "대략 생각하는 금액(추정)", 작은 글씨의 필요 서류 안내. 사람·물건 카드 맨 아래 합계 칸.
- 각 단계 아래 "모르면 건너뛰기". 건너뛴 값은 검토서의 "입력 필요" 목록에 모은다.

## 8. 보상 검토서(위에서 결론, 아래로 근거)
- 맨 위: 확정 기준 받을 돈, 추정 포함 받을 돈, 내가 낼 돈 + 추정 고지.
- 받을 곳별 합계(상대 보험, 내 보험, 정부보장사업).
- 사람·물건 카드별 담보 표: 확정액, 추정 포함액, 추정분, 계산식, 약관 조항, 면책 사유.
- 과실 시나리오 표, 입력 필요 목록(빠진 값과 그 값을 넣으면 생기는 항목), 필요 서류 체크리스트(담보별), 다음 할 일(어느 보험사에 무엇부터).
- 엑셀(시트 3개: 요약, 담보별 상세, 필요 서류)과 PDF(A4 세로)로 저장.

## 9. AI 기능
- 서버 API 라우트에서만 ANTHROPIC_API_KEY를 쓴다. 기본 모델 claude-sonnet-5-5.
- 서류 인식: 이미지를 서버에 저장하지 않는다. 주민번호·증권번호·차량번호·전화번호는 가리고 보험 정보만 돌려준다. 인식값은 사용자가 확인 버튼을 눌러야 확정 칸에 들어간다.
- 음성: V2의 음성→문자 변환 방식을 재사용하고 키 이름도 V2와 같게 맞춘다.
- 키가 없으면 "직접 입력해 주세요"를 띄우고 나머지 기능은 그대로 동작한다.

## 10. 배포
- Vercel Root Directory는 v6. 프로젝트 이름은 라운드 8(배포)에서 정한다(기존 kikhan-auto-compass-v4를 이어 쓸지 새로 만들지). 2026-10-21 확인한 Vercel 상태는 결정 기록 D-28.
- 환경변수는 칸이 Vercel 화면에서 직접 넣는다. 키 값을 채팅이나 코드에 쓰지 않는다.

## 11. 작업 방식
- 라운드 단위로 일한다. 지시받은 라운드 범위만 한다. 다음 라운드 일을 미리 하지 않는다.
- 라운드마다 테스트와 빌드가 통과하면 v6 폴더만 커밋한다. 푸시와 배포는 지시가 있을 때만.
- 막히거나 약관 해석이 갈리면 추측으로 진행하지 말고 질문으로 남긴다.
- v6 폴더 밖에는 어떤 파일도 만들지 않는다. 임시 파일은 `v6/.tmp/`(git 제외)에 둔다(결정 기록 D-10).
- 라운드가 끝나면 아래 형식 그대로 보고한다. 칸이 이 보고서를 그대로 복사해 Claude AI에게 검수받는다.

```
=== 라운드 N 보고서 ===
1. 완료한 것 (파일 경로 포함)
2. 테스트 결과 표 (사례 | 사람·물건 | 담보 | 확정액 | 추정 포함액 | 추정분 | 계산식 | 약관 조항)
3. 약관과 다르게 가정한 것 (standards.ts 항목)
4. 결정이 필요한 질문 (최대 5개, 선택지 포함)
5. 커밋 해시
=== 끝 ===
```

## 13. 라운드 2 테스트 사례
- 사례 (1)(2): 기준 금액(치료비, 상해급수, 소득 등)은 개발 책임자가 정한다. 보고서에는 **입력값 표를 먼저** 적고 그다음 결과 표를 적는다.
- 사례 8(고정): 내 과실 100%, 대물 한도 2천만 원, 수리비 확정 1,900만 원 + 렌트 추정 300만 원
  → 확정 1,900만 원, 추정 포함 2,000만 원, 추정분 100만 원.
  (추정 포함 손해 2,200만 원이 한도 2,000만 원에 걸리므로 추정분은 300만 원이 아니라 100만 원이다. 5장의 "단순 덧셈 금지" 검증용.)

# 2부. 라운드 0 결정 사항 (2026-10-21, 칸)

## B-1. 작업 폴더

# 3부. 약관 대조: 별표4 치료관계비 하한

방법: `data/raw/policies/` 4개 PDF에서 글자를 뽑은 뒤 별표4 「1. 과실상계 가. 과실상계의 방법」 (1)~(3)과 (*1)을 유니코드 정규화(NFKC)하고 공백·줄바꿈을 지워 글자 단위로 비교했다.

| 약관 | 별표4 위치(PDF 쪽 / 인쇄 쪽) | 비교 글자 수 | 개인용과 비교 |
|---|---|---|---|
| 개인용 (하이카 개인용자동차보험) | PDF 84–85 / 82–83 | 625 | 기준 |
| 업무용 | PDF 45 / 43 | 625 | **같음** |
| 영업용 | PDF 45 / 43 | 625 | **같음** |
| 이륜차 | PDF 45 / 43 | 625 | **같음** |

비교한 조항(네 약관 공통):
- (2) 대인Ⅰ 부상: 상계 후 금액 < 치료관계비+간병비이면 **대인Ⅰ 한도 내에서** 치료관계비(입원 식대 포함)와 간병비를 보상.
- (3) 대인Ⅱ·무보험차상해: 상계 후 금액 < 치료관계비+간병비이면 치료관계비(**대인Ⅰ 지급 가능액 공제**)와 간병비를 보상. 다만 **차량운전자**가 12~14급이고 상계 전 치료관계비가 대인Ⅰ 한도를 넘으면, 보험사는 우선 보상한 뒤 초과액 × 피해자 측 과실비율을 청구할 수 있다.
- (*1) "차량운전자"의 차량은 자동차관리법상 자동차(**이륜자동차 제외**)·군수품 차량·건설기계이며, 피해자 측 과실비율을 적용받는 자를 포함한다.

V2의 `compass/data/rules/product-check.json`도 업무용·영업용·이륜차의 「치료비 보장」·「경상환자 규정」을 `same: true`로 적어 두었다. 이번 대조 결과와 일치한다.

결론: 문구는 네 약관이 같다. 그래도 B-3에 따라 `productLines`는 `["personal"]`로 두고, 다른 상품에는 "미검증" 표시를 붙인다. 범위를 넓힐지는 4부 Q1에서 칸이 정한다.

# 4부. 열린 질문 (라운드 0)

라운드 0 보고서의 4번 항목과 같다. **칸이 2026-10-21 라운드 0 검수에서 답했다. 결정은 5부 결정 기록에 있다.** 아래는 질문 원문을 기록으로 남긴 것이다.

**Q1. medicalFloor 적용 범위**
네 약관의 별표4 문구가 같다(3부).
- (가) B-3대로 `["personal"]`을 유지하고 다른 상품에는 "미검증" 표시를 붙인다.
- (나) 3부 대조를 근거로 `productLines`를 4개 상품으로 넓히고 "미검증" 표시를 뺀다.

덧붙여, (*1)에 따라 **이륜차 운전자는 "차량운전자"가 아니므로** 경상 구상 대상이 아니다. compass는 `vehicleDriver`("자동차(이륜자동차 제외)의 운전자인지")로 이를 구분한다. v6도 이륜차 운전자 피해자에게는 구상 없이 하한 전액을 적용하는지 확인이 필요하다.

**Q2. 음주·무면허·마약·조치의무 위반 (1부 6-(1)과 약관의 차이)**
설계는 "담보는 지급하되 사고부담금 표시"라고 한다. 개인용 약관 제11조(인쇄 50쪽)와 31쪽 안내표는 다음과 같다.
- 사고부담금: 대인Ⅰ은 한도 내 지급보험금 **전액**, 대인Ⅱ는 1사고당 1억 원, 대물은 의무한도(2천만 원) 이하 손해 전액 + 초과 손해 1사고당 5천만 원.
- **자기차량손해는 음주·무면허·마약이면 미보상**이다(제23조 14호, 인쇄 55쪽). 조치의무 위반(뺑소니)만 보상한다.
- 사고부담금 대상에 "사고발생 시 조치의무 위반"(도주)도 들어간다. 설계에는 이 항목이 없다.

선택지:
- (가) 약관대로 자차를 면책 처리하고, 조치의무 위반을 추가한다.
- (나) 설계 문구를 유지한다(권하지 않음).

**Q3. 지급액 조정 순서와 경상 구상 표시 (1부 6-(4)·(5))**
- 순서: 설계 순서는 "하한 → 구상 → 한도 → 중복 차감"이다. 약관 별표4 (3)과 compass `excessOverCompulsory()`(fault.ts 77–87행)는 **대인Ⅰ 지급 가능액을 먼저 공제하고 그다음 대인Ⅱ·무보험차상해 한도를 적용**한다. 한도가 유한할 때 두 순서의 결과가 달라진다.
  - (가) 약관·compass 순서(공제 → 한도)를 따른다.
  - (나) 설계 순서를 따른다.
- 구상 표시: 약관은 "과실상계 없이 우선 보상한 후 … 청구할 수 있음"이다. compass는 하한을 (치료관계비·간병비 − 구상액)으로 낮춰 받을 돈을 줄인다.
  - (가) compass대로 받을 돈에서 바로 뺀다.
  - (나) 받을 돈은 우선 보상 전액으로 두고, 구상액은 "내가 낼 돈"에 따로 적는다. 합계는 같고 보이는 방식만 다르다.

**Q4. 동승자 처리 (1부 6-(2))**
- 호의동승 감액: 별표4 3호는 "피보험자동차에 동승한 자"를 별표5로 감액한다고 하며, 가족·남을 나누지 않는다. 설계는 남 동승자에게만 "검토 표시"를 한다. → (가) 가족 동승자에게도 감액 검토를 표시한다. (나) 남 동승자에게만 표시한다.
- 받을 곳 나누기: 과실 없는 동승자에게는 두 차량 측이 공동으로 배상한다. 설계는 "상대 대인(상대 과실분) + 내 대인"으로 나눈다. → (가) 과실비율로 나눠 보여 주되 "어느 쪽에 전액 청구해도 된다"고 안내한다. (나) 과실비율 분담만 보여 준다.

**Q5. 라운드 2 테스트 사례 (1부 12장)**
- 사례 목록: MASTER.md에는 사례 (1)(2)와 8만 있고, (1)~(7)이 각각 어떤 사고인지는 정의되어 있지 않다. → (가) 칸이 사례 (1)~(7)의 사고 유형을 준다. (나) 개발 책임자가 6장 담보 매칭 7가지(나·가족 동승자·남 동승자·상대방·내 차·상대 차·무보험)를 순서대로 사례 (1)~(7)로 삼고 라운드 2 보고서에 입력값 표를 먼저 적는다.
- 사례 8의 한도 초과분: 추정 포함 손해 2,200만 원 중 한도를 넘는 200만 원은 6장 "한도 초과분은 본인 부담"에 해당한다. → (가) "내가 낼 돈"에 추정분 200만 원으로 표시한다(확정 기준 내가 낼 돈은 0원). (나) 사례 8은 받을 돈만 검증하고 내가 낼 돈은 보지 않는다.

## 라운드 0 검수 (2026-10-21)

**D-1. 이식 로직 테스트 방식** (라운드 0 Q6 → (가))
- 원본 테스트를 V2 엔진째로 옮기지 않는다. 같은 사례의 손 검산 숫자를 이식 함수에 직접 넣어 시험한다.
- 원본 테스트 파일·줄 번호와 기대값을 나란히 적은 대조표를 `tests/legacy/README.md`에 둔다.

**D-2. medicalFloor 적용 범위** (Q1)
- 이식 규칙 `legacy/data/fault.json`은 원본 그대로 `productLines: ["personal"]`로 둔다.
- 업무용·영업용·이륜차는 약관 PDF에서 두 조항을 찾아 개인용과 대조한다. 같다고 확인된 종류만 v6 쪽(`lib/engine/rule-verification.ts`)에서 productLines에 더한다. 다르거나 찾지 못하면 '미검증'을 유지한다.
  - 치료관계비 하한: 별표4 1.가.(2)·(3)
  - 경상(12~14급) 본인 과실분 치료비: 별표4 1.가.(3) 단서와 (*1)
- 대조 결과(3부 표): 세 종류 모두 PDF 45쪽(인쇄 43쪽)에 있고, 625자가 개인용과 같다. 그래서 `fault.medicalFloor`·`fault.minorInjuryGrades`에 business·commercial·motorcycle을 더했다.
- 남은 '미검증': `rounding.won`(원 미만 처리)은 약관에 없는 값이라 그대로 '미검증'이다.
- 이륜차 운전자는 (*1) "차량운전자"(이륜자동차 제외)가 아니다. 그래서 경상 구상 대상이 아니다. 입력의 `vehicleDriver`를 false로 둔다.

**D-3. 음주·무면허·마약(·조치의무 위반)** (Q2)
- 대인Ⅰ·대인Ⅱ·대물배상은 지급하고, 사고부담금을 "내가 낼 돈"에 표시한다. 사고부담금은 개인용 약관 제11조(인쇄 50쪽)를 따른다.
  - 대인Ⅰ: 한도 내 지급보험금 전액
  - 대인Ⅱ: 1사고당 1억 원
  - 대물: 의무한도 2천만 원 이하 손해 전액 + 초과 손해 1사고당 5천만 원
  - 제11조는 조치의무 위반(도주)도 사고부담금 대상으로 정한다.
- 자기차량손해는 면책이다. 근거는 제23조 14호(개인용 인쇄 55쪽, 업무용·영업용·이륜차 제23조 14호 같은 문구)다.
  - 다만 이 면책은 운전자가 다음 중 하나일 때만 적용된다: 보험계약자·기명피보험자, 30일 넘는 임대차의 임차인, 기명피보험자와 같이 살거나 생계를 같이하는 친족. (→ 라운드 1 질문 Q1)
  - 조치의무 위반만 있는 경우 자기차량손해는 보상한다(개인용 인쇄 31쪽 안내표).
- 자기신체사고·자동차상해는 4개 약관 PDF에서 확인한 결과 **면책 사유가 아니다**(아래 표). 그래서 '검토 필요' 표시는 붙이지 않는다.

| 약관 | 자기신체사고 「보상하지 않는 손해」 | 자동차상해 특별약관 「4. 보상하지 않는 손해」 | 결과 |
|---|---|---|---|
| 개인용 | 제14조 1~7호(인쇄 51쪽): 고의·시험/경기용·전쟁·천재지변·핵·영리 유상운송. 음주·무면허·마약 없음 | (1) 운전자 범위 밖 운전자, (2) 보통약관 제14조 준용(인쇄 120쪽). 음주 등 없음 | 지급 |
| 업무용 | 1~8호(인쇄 11–12쪽): 위와 같고 8호 정규 승차장치 아닌 곳 탑승. 음주 등 없음 | (1)(2) 같음(인쇄 86쪽) | 지급 |
| 영업용 | 1~8호(인쇄 11–12쪽): 같은 구성. 음주 등 없음 | (1)(2) 같음(인쇄 75쪽) | 지급 |
| 이륜차 | 1~8호(인쇄 11–12쪽): 같은 구성. 음주 등 없음 | 이륜차 약관에는 자동차상해 특별약관이 없다 | 자기신체사고 지급 / 자동차상해 해당 없음 |

  개인용 인쇄 31쪽 안내표도 음주·무면허·조치의무 위반·마약일 때 자기신체사고·자동차상해·무보험차상해를 "보상"으로 적는다.

**D-4. 공제와 한도 순서, 경상 구상 표시** (Q3)
- 뒤 순위 지급 = min(뒤 순위 한도, 실제손해 − 앞 순위 지급액). 이식 코드 `excessOverCompulsory()`(공제 → 한도)와 같다.
- 경상 본인 부담분(구상)은 받을 돈에서 말없이 빼지 않는다. "내 자동차상해·자기신체사고에서 처리" 줄로 따로 표시한다. (엔진 연결 라운드에서 구현)

**D-5. 호의동승** (Q4)
- 자동 감액하지 않는다. `Victim.rideAlongReductionPercent`의 기본값은 0%다.
- 사용자가 별표5 비율을 고르면 적용하고 '검토 필요'를 표시한다. 가족·남 동승자 모두 같다.

**D-6. 라운드 2 사례 목록** (Q5)
- 칸: "MASTER.md에 고정한 8개 그대로. 사례 4의 대인Ⅰ 상당액은 정부보장사업으로 계산."
- 현재 MASTER.md 1부 12장에는 사례 (1)(2)의 기준과 사례 8만 있다. (3)~(7)의 사고 유형은 문서에 없다. (→ 라운드 1 질문 Q2)

**D-7. 지급처와 표시 이름** (라운드 0 보완 1)
- 상대 차량이 무보험·뺑소니이면 대인Ⅰ 금액의 이름은 "대인Ⅰ 상당액(정부보장사업)"이고, 지급처는 정부보장사업이다(자동차손해배상보장법 제30조).
- legacy 계산 본문은 그대로 두고, 이름과 지급처는 `lib/claim/payer.ts`가 붙인다.

**D-34. 검토서·내보내기에서 개발이 정한 것**
- 화면·엑셀·PDF는 같은 검토서 모델(`lib/report/review.ts` buildReview) 하나를 쓴다. 모델의 모든 글자는 개인정보 가림(`lib/privacy/mask.ts`)을 거친다.

- 엑셀은 exceljs, 시트 3개(요약·담보별 상세·필요 서류). 금액은 숫자 칸(#,##0). 긴 글은 A~D 열을 합친다.

- 필요 서류 체크 칸은 화면에서만 누를 수 있고 저장하지 않는다(PDF는 빈 네모, 엑셀은 □).
- 상대 대인Ⅱ 가입 여부를 모르면 과실 시나리오 표에 "있음/없음" 줄을 함께 둔다.

## 라운드 6c (2026-10-22, 칸 지시)

**D-38. 일용근로자 임금을 쓰는 휴업손해는 월 환산**
- 1일 수입감소액 = 월 임금(일급 × 25일) ÷ 30. 그 뒤 85%와 휴업일수를 곱한다. 원 미만은 단계마다 버린다(÷30 뒤, ×85% 뒤).
- 표시: "월 ○원(일 ○원 × 25일) ÷ 30 × 85% × ○일 = ○원". 예: 2026-09-01, 가사종사자 10일 → 950,810원.
- 월소득을 넣는 유직자 휴업손해(월소득 × 일수 × 85% ÷ 30, 마지막에 한 번 버림)는 바꾸지 않았다.
- 단순노무종사원 단가표: 2026-01-01 90,694원(2025 하반기 조사, 2025-11-27 발표, 적용일 추정 → 결과에 "적용일 추정"), 2026-07-01 95,767원(2026 상반기 조사, 2026-06-29 발표). 2026-01-01 전은 '입력 필요'.
- 일용근로자 임금을 쓰는 다른 항목(상실수익·간병비·가정간호비·영업손실)은 자동 산정하지 않는다. 점검 결과는 round-6c.md.

**D-39. 음성·서류 인식에서 정한 것**
- 서류·증권 인식: Claude `claude-sonnet-5-5`, 구조화 출력(`messages.parse` + zod 스키마), effort low. PDF는 문서 블록 그대로, HEIC는 서버에서 JPEG로 바꿔 보낸다. Sonnet 5.5는 강제 tool_choice를 받지 않아 구조화 출력을 쓴다.

- 화면: 1단계 "말로 설명하기"(음성 → 확인 칸 → 경위에 넣기), 3단계 "증권 사진·PDF로 채우기", 6단계 "영수증·진단서(견적서) 사진으로 채우기". 보상 서류에서 옮기는 항목: 사람 카드 치료비·향후치료비·간병비·구조수색비와 입원·통원일수·월 소득, 물건 카드 수리비·대차료·휴차료·견인비.
- 서버 측 거절 대비(fallbacks)는 켜지 않았다. Sonnet 5.5의 서버 측 fallback은 cyber·frontier_llm 거절만 다시 시도하는데 보험 서류 옮겨 적기와 관계가 없다. 거절(refusal)이면 503 "준비 중"으로 돌린다.

## 라운드 8 배포 (2026-10-22, 칸 지시)

**D-41. 공개 앱의 비용 보호**
- 서류 인식·음성 API는 IP당 하루 20회(라운드 8c에서 30회, D-43)(두 API 합산, 한국 시간 0시에 다시 셈). 넘으면 429와 "오늘 사용 횟수를 다 쓰셨어요. 직접 입력해 주세요". 나머지 기능은 그대로 쓴다(`lib/ai/limits.ts`).
- 횟수는 제공자를 실제로 부를 때만 센다(형식·크기 오류로 끝난 요청은 세지 않는다).
- 횟수는 서버 메모리에만 센다. 외부 저장소(데이터베이스)를 새로 두지 않으려는 것이다. 인스턴스가 여러 개거나 다시 시작하면 따로·처음부터 세므로 상한이 정확하지 않다(round-8.md 남은 위험).
- 업로드: 화면에서 한 번에 5건, 한 건 10MB까지 고를 수 있고 서버로는 한 건씩 차례로 보낸다(서버는 한 요청 두 건 이상이면 400). 사진은 브라우저에서 줄여 4MB 안으로 보낸다. Vercel 함수의 요청 본문 한도(4.5MB) 때문에, 줄이지 못한 4MB 초과 파일(큰 PDF, 크롬·안드로이드의 큰 HEIC)은 보내지 않고 사진으로 찍어 올리라고 안내한다.

## 라운드 8b 보완 (2026-10-22, 칸 지시)

**D-42. 큰 PDF, 여러 서류가 같은 칸을 읽을 때**
- 4MB가 넘는 PDF는 브라우저에서 pdf.js(legacy 빌드, 작업 파일은 빌드 전에 public/pdfjs로 복사)로 앞 5쪽까지 쪽마다 긴 변 2000px JPEG로 그려 한 쪽씩 보낸다. 5쪽을 넘으면 "앞 5쪽만" 안내. 서버에는 저장하지 않는다(D-41 그대로). 쪽마다 하루 한도 1회를 쓴다.
- 금액 칸: 서류마다 한 줄씩 쌓는다(덮어쓰지 않음). 줄마다 기관명·서류 날짜를 함께 두고, 체크를 풀면 합계에서 뺀다. "합계로 확인"을 누르면 체크한 줄의 합계가 확정 칸에 들어간다. 날짜·금액·기관명이 같은 줄은 "같은 서류로 보여요"(날짜·기관명을 못 읽은 경우 둘 다 못 읽었으면 같다고 본다).
- 일수 칸(입원·통원·휴업)과 월 소득: 더하지 않는다. 한 줄에 서류별 값을 모아 가장 큰 값을 넣고, 값이 다르면 "서류마다 다르게 적혀 있어요"와 각 값을 보여 준다. 휴업일수(daysOffWork)를 서류에서 읽는 칸에 더했다.
- 서류 인식 스키마에 issuer(발행 기관)·documentDate(서류 날짜)·facts.daysOffWork를 더했다. 저장 모양은 선택 칸만 늘어 예전 저장값이 그대로 읽히므로 저장 버전(7)은 올리지 않았다.
- 증권 값은 지금처럼 새로 읽으면 바꾼다.

**D-45. 라운드 9: 증권 먼저, 드롭다운, 차량가액 추정, 약관 질의(칸 지시로 기능 동결 해제)**
- 화면 순서: 증권·가입증명서 올리기 → 사고일(보험기간 점검) → 증권에서 못 읽은 칸만(내 보험·가입담보·가입금액) → 사고 당시 상황 → 사람·물건 → 상대 차량 보험 → 과실비율 → 손해 → 보상 검토서. 증권에서 읽어 확인한 칸은 `claim.policyRead`에 적고 그 질문을 건너뛴다. 저장 버전 8.
- 증권 인식은 보험기간·연령 한정특약·차종·연식·차량가액(차량가입금액)도 읽는다. 읽은 값은 표 한 장(담보 | 가입금액 | 확인)과 [모두 확인] 한 번으로 넣는다.
- 선택형 질문은 모두 드롭다운, 첫 항목 '모름'. '모르면 건너뛰기'는 없앴다. 결과를 바꾸지 않는 사고 장소·경위 질문은 뺐다(값은 저장 모양에 남김).
- 상대 차량 보험 '모름'은 일반적 가입 기준(대인배상Ⅱ 무한·대물배상 2억 원)으로 계산하고 검토서 안내에 적는다. 뺑소니·무보험 사고 유형이면 채우지 않는다.
- 사고 직전 차량가액은 묻지 않는다. 내 차는 증권 차량가액, 그 밖은 차종 등급·연식으로 앱이 추정(등급별 대표 신차가격 × 경과연수 잔존율, 앱이 정한 근사값, '추정' 표시). 수리비용이 사고 직전 가액의 120%를 넘으면 사고 직전 가액으로 계산하고 '전부손해 가능성'과 근거(별표2 1. 나.(3)·2., 인쇄 80쪽)를 붙인다. 130% 예외는 판단하지 않는다.
- 약관 질의: 약관 4종 원문을 쪽마다 뽑아(`scripts/build-terms.mjs` → `lib/terms/data.json`) 앱에 넣고, 질문 낱말로 관련 쪽 10개를 찾아 사고 사실과 함께 Claude에 묻는다. 서버가 인용 쪽·문구를 원문과 대조하고, 대조되지 않으면 '원문에서 확인되지 않음'. 법령은 `LAW_API_OC`가 있을 때만 국가법령정보센터에서 가져온다(없으면 법령·판례는 '원문에서 확인되지 않음'). 하루 한도는 서류 인식·음성과 합산.


**D-46. 라운드 9b: 키 만료 대비, 법령 원문 연결 준비, 다친 사람의 위치**

- Next.js 16.4.0 → 16.4.6(eslint-config-next 함께). 실증권 검증은 tests/fixtures/private/(커밋 금지)에 파일이 없어 하지 못했다.


**D-47. 라운드 9c: 공동불법행위 안내, 미계산 표시**
