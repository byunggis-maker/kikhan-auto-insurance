# 키칸 자동차보험 보상 나침반 V6 — 마스터 설계

> 이 문서는 모든 라운드의 기준이다. 1부는 칸이 정한 설계 원문, 2부는 라운드 0에서 칸이 답한 결정 사항, 3부는 옮겨 올 V2 로직의 출처, 4부는 약관 대조 결과, 5부는 아직 열린 질문이다.
> 1부와 2부가 충돌하면 2부(나중 결정)가 우선한다.

---

# 1부. 설계 원문

역할: 칸이 방향을 정하고, 별도 채팅의 Claude AI가 보고서를 검산한다. 개발 책임자(Claude Code)는 만들고 보고한다.

## 1. 앱의 목적
- 사고 낸 운전자 본인이 보상담당자 없이 "누가, 어느 보험에서, 어떤 담보로, 대략 얼마를, 무슨 서류로" 받는지 추정하게 한다.
- 화면과 계산은 보상담당자의 처리 순서를 따른다: 사고 접수 → 면책·제한 확인 → 사람·물건 정리 → 담보 매칭 → 손해액 산정 → 지급액 조정 → 서류 안내.
- 계산 단위는 담보가 아니라 사람 한 명, 물건 한 개다. 운전자, 동승자 각각, 상대방을 따로 카드로 만든다.

## 2. 절대 규칙
- 로그인, 비밀번호, 카카오 인증 없음. 주소만 열면 바로 쓴다.
- Supabase를 포함한 어떤 데이터베이스도 쓰지 않는다. 사고 정보는 서버에 저장하지 않고, 진행 상태는 브라우저 localStorage에만 저장한다(읽기·쓰기 모두 try/catch).
- 모든 금액 옆에 계산식과 약관 조항(별표 번호)을 표시한다.
- 결과 화면 맨 위에 "추정액이며 확정 금액은 보험사가 정합니다"를 표시한다.
- 작업은 v6/ 안에서만. compass/(V2), v4/, Streamlit 파일은 읽기만 하고 수정하지 않는다.
- 화면 글자는 전체적으로 진하게. 추정 값과 인식된 값만 연한 청색 계열로 구별한다.

## 3. 근거 자료(우선순위 순)
- data/raw/policies/ 안의 자동차보험 약관 PDF(개인용, 업무용, 영업용, 이륜차). 별표 지급기준이 계산의 최종 근거다.
- 자동차손해배상보장법과 시행령(책임보험 한도, 상해급수 표, 정부보장사업).
- V2 코드는 부품 참고용이다. 음성→문자 변환, 증권·서류 인식(PDF, HEIC, JPEG), 개인정보 가림, 엑셀 저장만 참고해 다시 구현한다. V2의 화면 순서와 담보 단위 계산은 쓰지 않는다. (예외: 2부 B-2)
- 약관과 다르게 가정한 값과 금액 기준(한도, 사고부담금, 일용근로자 임금 등)은 v6/lib/claim/standards.ts 한 파일에 근거와 함께 모으고, 보고서에 반드시 적는다.

## 4. 데이터 구조
- Accident: 일시, 장소, 경위, 사고 유형(차대차, 차대사람, 단독, 뺑소니·무보험).
- Policy(내 보험·상대 보험): 보험 종류(개인용·업무용·영업용·이륜차), 보험사, 가입담보와 가입금액, 운전자 범위, 자기부담금, 대인Ⅱ 가입 여부.
- Victim: 운전자 본인 / 가족 동승자 / 남 동승자 / 상대방. 사람마다 카드 1개. 기명피보험자와의 관계 포함.
- Property: 내 차 / 상대 차·물건. 물건마다 카드 1개.
- LossItem: 항목 코드, confirmed(확정 금액, 서류 근거), estimated(추정 금액), source(서류 | 약관 기준 | 사용자 추정 | 앱 기본값), requiredDocs(필요 서류 목록).
- 카드마다 userTotal(사용자가 직접 넣는 합계 추정).

## 5. 확정·추정 이중 계산
- 확정 계산: confirmed 값만으로 엔진을 실행한다.
- 추정 포함 계산: confirmed가 빈 칸만 estimated로 채워 엔진을 다시 실행한다.
- 추정분 = 두 결과의 차이. 단순 덧셈 금지(하한·한도·자기부담금 때문에 비선형).
- 같은 칸에 둘 다 있으면 confirmed 우선. estimated는 참고로 청색 표시.
- 둘 다 없으면 "입력 필요"로 남기고 합계에 넣지 않는다.
- 항목 없이 userTotal만 있으면 "항목 미분류 손해(추정)"로 계산하고 치료관계비 하한은 적용하지 않는다. "항목을 나누면 더 정확해집니다"를 안내한다. 항목과 userTotal이 둘 다 있고 다르면 차이를 표시한다.
- 결과는 담보별·사람별로 확정액, 추정 포함액, 추정분을 따로 낸다.

## 6. 계산 엔진 순서
(1) 면책·제한
- 음주·무면허·마약: 담보는 지급하되 사고부담금을 "내가 낼 돈"에 표시.
- 운전자 범위 위반: 대인Ⅰ과 대물배상 의무가입한도(2천만 원)까지만 지급, 나머지 담보는 면책 표시.
- 기명피보험자의 부모·배우자·자녀는 내 대인Ⅱ 면책.
- 고의 사고: 계산하지 않고 안내만.

(2) 담보 매칭
- 나(운전자) → 상대 대인Ⅰ·Ⅱ, 부족분·내 과실분은 내 자동차상해 또는 자기신체사고
- 가족 동승자 → 상대 대인(상대 과실분) + 내 대인Ⅰ, 내 대인Ⅱ는 면책, 부족분은 내 자동차상해
- 남 동승자 → 상대 대인 + 내 대인Ⅰ·Ⅱ(공동 배상), 호의동승 감액 검토 표시
- 상대방 → 내 대인Ⅰ·Ⅱ, 보험료 할증 안내
- 내 차 → 상대 대물(상대 과실분) + 내 자기차량손해(내 과실분 − 자기부담금)
- 상대 차·물건 → 내 대물배상, 한도 초과분은 본인 부담
- 무보험·뺑소니 → 내 무보험차상해, 미가입이면 정부보장사업

(3) 손해액 산정: 약관 별표 기준으로 치료관계비, 향후치료비, 휴업손해, 위자료, 상실수익, 수리비, 대차료·휴차료, 시세하락, 견인비.

(4) 지급액 조정: 과실상계 → 치료관계비 하한 → 경상(12~14급) 운전자 구상 → 담보 한도 → 자기부담금.

(5) 중복 차감: 뒤 순위 담보는 "실제손해 − 앞 순위 지급액"만 준다.
- 과실을 모르면 0·30·50·70% 시나리오를 한 번에 계산한다.
- 현재 v6의 treatmentFloor, 경상 구상, 중복 차감 로직은 약관 검증을 마쳤으니 재사용한다. (→ 2부 B-2: 실제로는 compass 코드)
- 사람별 지급 합계는 그 사람의 실제손해를 넘을 수 없다.

## 7. 화면 7단계(모바일 우선, 한 화면에 질문 하나)
1 사고 접수(음성 또는 글) → 2 사람·물건 정리 → 3 내 보험(증권 사진 인식 또는 직접 입력) → 4 상대 보험 → 5 면책·과실(과실 모르면 범위 선택) → 6 손해 입력 → 7 보상 검토서.
- 6단계 청구란: 가입담보에 있는 담보만 보인다. 손해 항목 하나 = 카드 하나. 카드에 항목 이름과 한 줄 설명, "서류로 확인한 금액(확정)", "대략 생각하는 금액(추정)", 작은 글씨의 필요 서류 안내. 사람·물건 카드 맨 아래 합계 칸.
- 각 단계 아래 "모르면 건너뛰기". 건너뛴 값은 검토서의 "입력 필요" 목록에 모은다.

## 8. 보상 검토서(위에서 결론, 아래로 근거)
- 맨 위: 확정 기준 받을 돈, 추정 포함 받을 돈, 내가 낼 돈 + 추정 고지.
- 받을 곳별 합계(상대 보험, 내 보험, 정부보장사업).
- 사람·물건 카드별 담보 표: 확정액, 추정 포함액, 추정분, 계산식, 약관 조항, 면책 사유.
- 과실 시나리오 표, 입력 필요 목록(빠진 값과 그 값을 넣으면 생기는 항목), 필요 서류 체크리스트(담보별), 다음 할 일(어느 보험사에 무엇부터).
- 엑셀(시트 3개: 요약, 담보별 상세, 필요 서류)과 PDF(A4 세로)로 저장.

## 9. AI 기능
- 서버 API 라우트에서만 ANTHROPIC_API_KEY를 쓴다. 기본 모델 claude-sonnet-5-5.
- 서류 인식: 이미지를 서버에 저장하지 않는다. 주민번호·증권번호·차량번호·전화번호는 가리고 보험 정보만 돌려준다. 인식값은 사용자가 확인 버튼을 눌러야 확정 칸에 들어간다.
- 음성: V2의 음성→문자 변환 방식을 재사용하고 키 이름도 V2와 같게 맞춘다.
- 키가 없으면 "직접 입력해 주세요"를 띄우고 나머지 기능은 그대로 동작한다.

## 10. 배포
- Vercel Root Directory는 v6. 프로젝트 이름은 라운드 6에서 정한다(기존 kikhan-auto-compass-v4를 이어 쓸지 새로 만들지).
- 환경변수는 칸이 Vercel 화면에서 직접 넣는다. 키 값을 채팅이나 코드에 쓰지 않는다.

## 11. 작업 방식
- 라운드 단위로 일한다. 지시받은 라운드 범위만 한다. 다음 라운드 일을 미리 하지 않는다.
- 라운드마다 테스트와 빌드가 통과하면 v6 폴더만 커밋한다. 푸시와 배포는 지시가 있을 때만.
- 막히거나 약관 해석이 갈리면 추측으로 진행하지 말고 질문으로 남긴다.
- 라운드가 끝나면 아래 형식 그대로 보고한다. 칸이 이 보고서를 그대로 복사해 Claude AI에게 검수받는다.

```
=== 라운드 N 보고서 ===
1. 완료한 것 (파일 경로 포함)
2. 테스트 결과 표 (사례 | 사람·물건 | 담보 | 확정액 | 추정 포함액 | 추정분 | 계산식 | 약관 조항)
3. 약관과 다르게 가정한 것 (standards.ts 항목)
4. 결정이 필요한 질문 (최대 5개, 선택지 포함)
5. 커밋 해시
=== 끝 ===
```

# 2부. 라운드 0 결정 사항 (2026-10-21, 칸)

## B-1. 작업 폴더
- `kikhan-auto-insurance-V6/v6/`를 새로 만들어 시작한다. 시작 시점에 v6/와 v4/는 둘 다 없었다.
- 읽기만 하는 것: 루트 `app.py`, `requirements.txt`(커밋 안 된 수정 포함), `compass/`, `insurance_ocr/`, `.streamlit/`.
- `kikhan-question -V4/v4`는 다른 앱이므로 무시한다.

## B-2. V2 코드 재사용 예외
1부 6-(5)의 "treatmentFloor·경상 구상·중복 차감"은 compass(V2)의 아래 코드를 말한다. **이 세 로직만** V2 코드를 v6로 옮겨 쓸 수 있다. 나머지 V2 담보 단위 계산은 쓰지 않는다. 출처는 3부에 적는다.

## B-3. 적용 범위
- `fault.medicalFloor`는 compass에서 `productLines: ["personal"]`로 검증된 상태 그대로 옮긴다. 범위를 임의로 넓히지 않는다.
- 업무용·영업용·이륜차 계약에서 이 로직이 호출되면 결과에 **"미검증: 해당 약관 대조 필요"** 표시를 붙인다.
- 업무용·영업용·이륜차 PDF에서 치료관계비 하한(별표4)을 찾아 개인용과 비교한다(4부). 문구가 다르면 값을 바꾸지 않고 질문으로 올린다.

# 4부. 약관 대조: 별표4 치료관계비 하한

| 약관 | 별표4 위치(PDF 쪽 / 인쇄 쪽) | 비교 글자 수 | 개인용과 비교 |

| 영업용 | PDF 45 / 43 | 625 | **같음** |
| 이륜차 | PDF 45 / 43 | 625 | **같음** |

비교한 조항(네 약관 공통):
- (2) 대인Ⅰ 부상: 상계 후 금액 < 치료관계비+간병비이면 **대인Ⅰ 한도 내에서** 치료관계비(입원 식대 포함)와 간병비를 보상.
- (3) 대인Ⅱ·무보험차상해: 상계 후 금액 < 치료관계비+간병비이면 치료관계비(**대인Ⅰ 지급 가능액 공제**)와 간병비를 보상. 다만 **차량운전자**가 12~14급이고 상계 전 치료관계비가 대인Ⅰ 한도를 넘으면, 보험사는 우선 보상한 뒤 초과액 × 피해자 측 과실비율을 청구할 수 있다.
- (*1) "차량운전자"의 차량은 자동차관리법상 자동차(**이륜자동차 제외**)·군수품 차량·건설기계이며, 피해자 측 과실비율을 적용받는 자를 포함한다.

V2의 `compass/data/rules/product-check.json`도 업무용·영업용·이륜차의 「치료비 보장」·「경상환자 규정」을 `same: true`로 적어 두었다. 이번 대조 결과와 일치한다.

결론: 문구는 네 약관이 같다. 그래도 B-3에 따라 `productLines`는 `["personal"]`로 두고, 다른 상품에는 "미검증" 표시를 붙인다. 범위를 넓힐지는 5부 Q1에서 칸이 정한다.

# 5부. 열린 질문 (라운드 0)

라운드 0 보고서의 4번 항목과 같다. 칸이 답하면 2부에 결정으로 옮긴다.

**Q1. medicalFloor 적용 범위**
네 약관의 별표4 문구가 같다(4부).
- (가) B-3대로 `["personal"]`을 유지하고 다른 상품에는 "미검증" 표시를 붙인다.
- (나) 4부 대조를 근거로 `productLines`를 4개 상품으로 넓히고 "미검증" 표시를 뺀다.

덧붙여, (*1)에 따라 **이륜차 운전자는 "차량운전자"가 아니므로** 경상 구상 대상이 아니다. compass는 `vehicleDriver`("자동차(이륜자동차 제외)의 운전자인지")로 이를 구분한다. v6도 이륜차 운전자 피해자에게는 구상 없이 하한 전액을 적용하는지 확인이 필요하다.

**Q2. 음주·무면허·마약·조치의무 위반 (1부 6-(1)과 약관의 차이)**
설계는 "담보는 지급하되 사고부담금 표시"라고 한다. 개인용 약관 제11조(인쇄 50쪽)와 31쪽 안내표는 다음과 같다.
- 사고부담금: 대인Ⅰ은 한도 내 지급보험금 **전액**, 대인Ⅱ는 1사고당 1억 원, 대물은 의무한도(2천만 원) 이하 손해 전액 + 초과 손해 1사고당 5천만 원.
- **자기차량손해는 음주·무면허·마약이면 미보상**이다(제23조 14호, 인쇄 55쪽). 조치의무 위반(뺑소니)만 보상한다.
- 사고부담금 대상에 "사고발생 시 조치의무 위반"(도주)도 들어간다. 설계에는 이 항목이 없다.

선택지:
- (가) 약관대로 자차를 면책 처리하고, 조치의무 위반을 추가한다.
- (나) 설계 문구를 유지한다(권하지 않음).

**Q3. 지급액 조정 순서 (1부 6-(4)·(5))**
설계 순서는 "하한 → 구상 → 한도 → 중복 차감"이다. 약관 별표4 (3)과 compass `excessOverCompulsory()`는 **대인Ⅰ 지급 가능액을 먼저 공제하고 그다음 대인Ⅱ·무보험차상해 한도를 적용**한다. 한도가 유한할 때 두 순서의 결과가 달라진다.
- (가) 약관·compass 순서(공제 → 한도)를 따른다.
- (나) 설계 순서를 따른다.

**Q4. 경상 구상의 표시 방법**
약관은 "과실상계 없이 우선 보상한 후 … 청구할 수 있음"이다. compass는 하한을 (치료관계비·간병비 − 구상액)으로 낮춰 받을 돈을 줄인다.
- (가) compass대로 받을 돈에서 바로 뺀다.
- (나) 받을 돈은 우선 보상 전액으로 두고, 구상액은 "내가 낼 돈"에 따로 적는다. 합계는 같고 보이는 방식만 다르다.

**Q5. 동승자 처리 (1부 6-(2))**
- 호의동승 감액: 별표4 3호는 "피보험자동차에 동승한 자"를 별표5로 감액한다고 하며, 가족·남을 나누지 않는다. 설계는 남 동승자에게만 "검토 표시"를 한다. → (가) 가족 동승자에게도 감액 검토를 표시한다. (나) 남 동승자에게만 표시한다.
- 받을 곳 나누기: 과실 없는 동승자에게는 두 차량 측이 공동으로 배상한다. 설계는 "상대 대인(상대 과실분) + 내 대인"으로 나눈다. → (가) 과실비율로 나눠 보여 주되 "어느 쪽에 전액 청구해도 된다"고 안내한다. (나) 과실비율 분담만 보여 준다.
