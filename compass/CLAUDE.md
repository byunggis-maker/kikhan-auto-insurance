# 키칸 자동차보험 보상 나침반 v2 — 작업 규칙

사고 당사자가 보상과 직원의 설명을 기다리지 않고, 자신이 아는 기초 정보(진단명, 수술 여부, 입원·통원 기간, 과실비율, 직업·소득, 차량 수리비 등)만으로 가입한 자동차보험 약관의 담보별 예상 보험금을 사람별로 추정해 보는 앱이다.
대상 약관은 개인용·업무용·영업용 자동차보험과 이륜자동차보험이다. 전체 설계는 `docs/PLAN.md`에 있다.

v2는 기존 나침반(`~/Projects/kikhan-auto-compass`, 카카오 로그인 + Supabase판, 이하 v1)의 코드를 이 폴더(`compass/`)로 복사해 고친다. 바뀌는 점은 세 가지다.

1. 로그인이 없다. 접속하면 바로 쓴다.
2. 서버에 DB가 없다. 사용자 기록을 서버에 저장하지 않는다(Supabase를 쓰지 않는다).
3. 증권·서류에서 개인 식별 정보를 가린 뒤에만 분석에 쓰고, 화면에는 보험 정보만 보인다.

## 작업 방식

- 한 번에 한 단계만 한다. 단계 목록은 `docs/PLAN.md` 8절에 있다.
- 각 단계 끝에 `npm run build`와 `npm test`를 둘 다 통과시킨 뒤 커밋하고 멈춘다. 통과하지 못하면 커밋하지 않고 실패 내용을 그대로 보고한다.
- 멈출 때 5줄 이내로 보고한다: 한 일, 검증 결과, 확인하지 못한 것, 다음 단계.
- 커밋할 때는 `git add compass/`처럼 이 폴더만 올린다. 바깥의 Streamlit 파일(`app.py`, `insurance_ocr/`, `tests/` 등)에는 사용자가 아직 커밋하지 않은 변경이 있으므로 함께 커밋하지 않는다.
- 이미 있는 코드는 버리지 않고 고친다. 엔진(`lib/engine`)과 규칙(`data/rules`)은 v1에서 검산을 마친 것이므로, 로그인·DB·신원정보와 관계없는 부분은 건드리지 않는다.
- 추가 서비스(DB, Redis, 외부 저장소, 유료 SaaS)는 설치·가입 전에 사용자에게 먼저 묻는다. npm 패키지도 새로 넣을 때는 이유를 보고에 적는다.
- 고치지 않는 곳(읽기만 한다):
  - 저장소 루트의 Streamlit 앱 전체(`compass/` 바깥의 모든 파일)
  - v1 `~/Projects/kikhan-auto-compass` (복사의 원본)
  - 원본 Streamlit 앱 `~/Projects/kikhan-auto-vercel-20261004-181037`
  - 기존 Vercel 프로젝트 `kikhan-auto-vercel`, `kikhan-auto-compass`
- Next.js는 16 버전이다. 기억과 다를 수 있으므로 코드를 쓰기 전에 `node_modules/next/dist/docs/`의 해당 안내를 읽는다. 미들웨어가 필요하면 `middleware.ts`가 아니라 `proxy.ts`를 쓴다.

## 설계 원칙 1 — 계산은 코드가 한다

합계가 흐트러지는 문제를 막기 위한 규칙이다. 예외를 두지 않는다.

1. LLM은 계산하지 않는다. LLM의 일은 두 가지뿐이다.
   - 문서·음성에서 사실을 뽑아 JSON 스키마로 채우기
   - 결과를 쉬운 말로 설명하기
2. LLM은 금액을 숫자로 바꾸지도 않는다. 증권의 "부상 3천만원" 같은 표현은 원문 그대로 받고, 원 단위 변환은 `lib/engine/money.ts`가 한다. 변환된 값은 사용자가 화면에서 확인한다.
3. 설명 문장에도 LLM이 숫자를 직접 쓰지 않는다. `{{cell:사람.담보.expected}}` 같은 자리표시를 쓰게 하고, 서버가 결과 행렬의 값으로 바꿔 넣는다. 자리표시가 아닌 금액이 문장에 있으면 그 설명은 버리고 기본 문장을 쓴다.
4. 모든 금액 계산은 `lib/engine` 안의 순수 TypeScript 함수가 한다. 순수 함수란 같은 입력에 항상 같은 결과를 내고, 네트워크·저장소·시계·환경변수를 읽지 않는 함수다. 기준일은 인자로 받는다.
5. 금액은 원 단위 정수로 다룬다. 비율 계산은 `decimal.js`로 하고 마지막에 한 번만 정수로 만든다. `number`의 소수 연산(`0.85 * x`, `/ 100`)은 금지한다. 원 미만 처리 방식은 규칙 데이터에 적힌 방식만 쓴다.
6. 지급기준 숫자는 코드에 쓰지 않는다. 상해급별 한도, 위자료, 기타손해배상금, 자기부담금 조건 등은 모두 `data/rules/*.json`에 둔다. `lib/engine` 안에 금액·비율·일수 상수가 있으면 잘못된 것이다.
7. 규칙 항목마다 근거 조항(약관명·별표·조항·쪽), 적용 시작일, 확인 상태(`confirmed` / `needs_check`)를 기록한다. 확실하지 않은 숫자는 지어내지 않는다. `needs_check`로 두고 화면에 "약관 확인 필요"라고 표시한다.
8. 결과는 사람 × 담보 행렬로 만든다. 합계는 `lib/engine/summarize.ts`의 합산 함수 하나가 행렬의 칸에서만 다시 더한다. 화면·엑셀·PDF·읽어주기 어디에서도 따로 더하지 않는다. 브라우저에 저장된 합계는 믿지 않고 읽을 때 다시 계산한다.
9. 모든 칸은 최소·예상·최대 세 값을 가진다.
10. 입력이 없는 담보는 0원이 아니다. "정보 부족: ○○을 입력하면 계산됩니다"로 표시한다. "입력하지 않음"과 "0원으로 확인함"은 자료형에서부터 구분한다(`null`과 `0`).

## 설계 원칙 2 — 로그인 없음, 서버 저장 없음

- 카카오 로그인, 가입, 계정, 세션 쿠키가 없다. 첫 화면 → 동의 → 내 보험으로 바로 간다.
- 서버에는 DB가 없다. Supabase 관련 코드(`@supabase/*`, `supabase/migrations`, `lib/auth`, RLS 테스트)는 걷어 낸다.
- API 라우트는 상태를 갖지 않는다. 요청에 필요한 입력을 다 받아 처리하고 돌려줄 뿐, 아무것도 남기지 않는다.
- 진행 중 입력과 결과는 사용자의 브라우저(`localStorage`)에만 둔다. "이 기기의 기록 모두 지우기" 버튼을 둔다. 다른 기기로 옮기거나 보관하려면 엑셀·PDF로 받게 안내한다.
- 동의 여부도 브라우저에 둔다(동의 문구 버전과 날짜). 서버는 유료 API 요청마다 동의 버전 값을 함께 받아 확인한다.
- 유료 API(증권 읽기, 음성 변환, 사고 사실 추출, 쉬운 말 설명, 읽어주기)의 남용은 `lib/guard/paid.ts`의 `paidGuard()`가 막는다(자세한 방식은 `docs/PLAN.md` 3절).
  - Cloudflare Turnstile 확인
  - 하루 사용 한도(IP당 하루 이용권 3장. Redis에는 IP HMAC·이용권 번호와 개수만 둔다. 자세한 것은 PLAN 3절)
  - IP 원문은 어디에도 남기지 않는다.

## 설계 원칙 3 — 개인정보: 가린 뒤에만 분석, 보험 정보만 보인다

| 구분 | 항목 | 처리 |
|---|---|---|
| 반드시 가림 | 주민등록번호, 이름, 전화번호, 주소, 이메일, 증권번호, 차량번호, 계좌번호, 카드번호 | 인식 단계에서 가린다. 가린 뒤의 내용만 분석에 쓰고, 화면·응답·브라우저 저장소에 남기지 않는다 |
| 남겨서 분석 (보험 정보) | 보험사명, 상품 종류(개인용 자동차보험·운전자보험 등), 가입 담보와 가입금액, 특약, 자기부담금, 보험기간 | 화면에 보이고 계산에 쓴다 |
| 계산에 필요해 남기는 차량 정보 | 차종, 연식, 차량가액, 운전자 범위·연령 한정 | 사람을 알아볼 수 없는 정보다. 자기차량손해·면책 판단에 쓴다 |
| 건강정보 | 진단명, 수술, 상해급수, 입원·통원 기간, 장해, 사망 여부 | 브라우저에만 저장. 음성 변환·사고 사실 추출로 서버·LLM에 보낼 때는 건강정보 동의가 있어야 한다 |
| 계산용 사람 정보 | 역할(운전자·동승자·상대방·보행자), 만 나이, 직업 유형, 월소득, 소득 증빙 여부, 과실비율 | 이름 대신 "운전자(나)", "동승자 1"처럼 역할 이름만 쓴다 |

- 가리기는 `lib/privacy/redact.ts` 한 곳에서 한다. 판독 결과·PDF 글자·전사문·사고 설명 글·읽어주기 글이 모두 이 함수를 거친다. 가린 자리는 `******`, 가린 건수만 화면에 알린다.
- 정규식으로 잡는 것: 주민번호 꼴, 차량번호 꼴(`12가3456`, `서울12가3456`, `123가4567`), 전화번호, 이메일, 증권번호처럼 보이는 긴 숫자·하이픈 묶음, 계좌번호 꼴, 카드번호 꼴(13~19자리, Luhn 검사). 이름·주소는 정규식만으로 다 잡을 수 없으므로 "계약자·피보험자·성명·주소·예금주" 같은 항목 이름 뒤의 값을 가리고, 판독 스키마에는 이 칸을 아예 두지 않는다.
- 금액(`30,000,000`, "3천만원"), 날짜, 상해급수, 과실비율은 가리면 안 된다. 테스트로 확인한다.
- 원본 이미지·PDF·음성은 요청 메모리에서만 다루고 저장하지 않는다. 브라우저 저장소에도 넣지 않는다.
- 요청 본문, 전사문, 판독 결과, 사고 원문은 로그에 남기지 않는다. 오류 메시지에는 제공자 응답 원문을 싣지 않는다.
- 모든 결과 화면 하단에 다음 문구를 넣는다: "참고용 추정이며 손해사정이나 보험금 지급 확정이 아닙니다"

## 기술 스택

- Next.js 16 (App Router) + TypeScript(strict) + Tailwind CSS 4
- DB 없음. 브라우저 `localStorage`만 쓴다.
- 남용 방지: Cloudflare Turnstile, 서버가 서명한 분석 이용권, Upstash Redis 카운터(REST API를 `fetch`로 부름. 4단계에서 쿠키 카운터·Firewall 대신 정함)
- 음성→문자: OpenAI 음성 전사 API(모델은 환경변수). 읽어주기: OpenAI TTS API.
- 증권·가입증명서 읽기: 비전 LLM. `VISION_PROVIDER=openai|anthropic`으로 선택.
- 법령: 국가법령정보센터 Open API.
- 검증: zod(스키마), vitest(테스트), fast-check(합산 불변식 테스트)
- 배포: Vercel 새 프로젝트 `kikhan-auto-compass-v2`, Root Directory는 `compass`

## 코드 규칙

- `lib/engine`은 `lib/engine`, `lib/schemas`, `decimal.js`만 import한다. `next`, `fetch`, `process.env`, `Date.now()`, `localStorage`를 쓰지 않는다. 규칙 데이터는 인자로 받는다.
- 화면 부품과 API 라우트는 금액을 더하거나 빼지 않는다. 엔진이 준 값을 보여주기만 한다.
- 담보 모듈은 금액 대신 "칸"을 돌려준다. 칸은 상태(계산됨 / 정보 부족 / 해당 없음 / 약관 확인 필요), 세 값, 손해 항목별 내역, 쓴 규칙의 id, 부족한 입력 목록을 가진다.
- 같은 사람의 같은 손해를 두 담보가 보상할 수 있을 때(예: 상대방 대인배상과 내 자동차상해)는 둘 다 칸에 표시하되, 합계에는 한 경로만 넣고 나머지는 "대체 경로·합계 제외"로 표시한다. 이 조정은 `lib/engine/coordinate.ts` 한 곳에서만 한다.
- 내가 받을 금액과 상대방에게 지급될 금액은 서로 더하지 않는다. 합계는 받는 사람 묶음별로 낸다.
- 본인 증권의 대인·대물 한도를 상대방 보험의 한도로 쓰지 않는다. 상대방 증권이 없으면 "상대방 계약 확인 필요"로 둔다.
- 사고일에 맞는 규칙만 쓴다. 맞는 규칙이 없으면 `needs_check`다.
- 외부에서 들어오는 모든 값(요청, LLM 출력, 브라우저 저장소에서 읽은 값)은 zod로 검증한 뒤에 쓴다.
- 신원정보 칸을 스키마·화면·브라우저 저장소에 만들지 않는다. 금지 이름: `insuredName`, `contractorName`, `displayName`, `policyNumber`, `vehicleNumber`, `plateNumber`, `rrn`, `birthDate`, `sex`, `gender`, `phone`, `address`, `email`, `accountNumber`, `cardNumber`. 사람 객체에는 이름 칸이 없고 역할 이름(`label`)만 있다. `tests/privacy-fields.test.ts`가 스키마에서 이 이름들을 찾으면 실패한다.
- 나이가 필요한 계산(상실수익액, 사망·후유장애 위자료)은 생년월일 대신 만 나이(`age`)를 받고, 생일을 모르는 만큼의 차이를 최소·최대로 낸다(`docs/PLAN.md` 7절 사람 JSON).
- 환경변수는 서버 전용이다. `NEXT_PUBLIC_` 접두사를 쓰지 않는다(Turnstile 사이트 키도 서버가 화면에 넘긴다). 비밀값은 `.env.local`에만 두고 `.env.example`에는 이름만 적는다.
- 엔진을 고치면 테스트를 함께 고친다. 담보 모듈마다 정상 사례, 정보 부족 사례, 한도 초과 사례, `needs_check` 규칙 사례를 둔다.
- 합산 불변식 테스트를 항상 유지한다: 칸의 합 = 사람별 합의 합 = 담보별 합의 합 = 총합계, 그리고 최소 ≤ 예상 ≤ 최대.
- 테스트와 fixtures에 실제 사람의 이름·차량번호·증권번호·주민번호·계좌·카드번호를 넣지 않는다.
- 주석과 화면 문구는 한국어로 쓴다. 식별자는 영어로 쓴다.
